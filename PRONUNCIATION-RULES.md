## User behavior

Optional draft controls accept one `spelling => spoken form` per line. These are literal substitutions, not phonemes, SSML, a name-pronunciation database, or a correctness guarantee. For example, a user can choose `Nebuchadnezzar => neb-uh-kad-NEZ-er`, then inspect and listen to the result. The manuscript textarea and downloaded reviewed source remain unchanged. A separate bounded preview shows original source and resolved engine input. The preview uses the same original 240-character passage boundaries as generation and shows at most 6,000 source characters, shortened at a complete passage boundary. Input scanning for that preview is capped at 6,240 characters.

Up to 32 rules, 1–80 UTF-16 characters per side, no line breaks/control characters, well-formed Unicode, nonempty trimmed entries. The `=>` delimiter cannot appear inside an entry in this simple editor; no escape language is interpreted. Regex metacharacters, backslashes, dollar signs and HTML-like text are literal. Unrecognized syntax and duplicate spellings under the selected case mode reject visibly. An invalid edited dictionary is still retained in the local draft, but cannot create audio; it is never silently treated as a valid empty dictionary during generation. Editing rules clears the source-review confirmation.

Matching chooses the earliest whole-token match, then the longest overlapping spelling, then rule order. Replacement forms are not rescanned (no cascades). Token characters are Unicode letters/marks/numbers and underscore; matches require a non-token character or source edge on either side; apostrophes and hyphens separate tokens, so a name may match before a possessive suffix. Case-insensitive matching uses JavaScript Unicode simple case folding: `K` and `K` match; `ß` does not expand to `ss`. There is no accent normalization or locale-specific expansion. Exact-case mode is available. See [MDN's Unicode-aware ignoreCase documentation](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/RegExp/ignoreCase).

Phrase rules do not span saved passage boundaries, and whitespace is literal. A phrase cut by an original chunk boundary will not match as a phrase; previews use those same boundaries. Resolved input over 960 characters per passage fails before committing new audio, with a request to shorten aliases. The existing engine token-limit rejection remains active; no truncation, automatic re-chunking or source rewriting is introduced.

Rules apply to new Studio recordings and their paragraph previews. Fixed auditions and Device Quick listen keep their existing original-text behavior, explicitly stated beside the controls. No rules are enabled automatically. These controls do not implement phonetic accuracy review, speech-error detection or cloning.

## Frozen provenance and saved recordings

Each nonempty dictionary is a canonical snapshot: schema, matcher version, draft revision counter, case mode and ordered literal rules. That snapshot is present in normalized settings and the frozen render manifest, whose existing SHA-256 binds the full content. The revision counter is local to a draft, not a globally unique dictionary ID; different content still yields different manifest/recording identity. Empty dictionaries omit the new settings/manifest fields, preserving historical identities when their original manifests are supplied.

The worker resolves each original passage immediately before inference; every voice engine receives that resolved string. It reports the string used. Pause accounting and `last` still use original source/position. The storage transaction checks the reported spoken string against the frozen rules and stores its SHA-256. Checkpoint validation and alternative-take validation recompute that hash. Generated takes preserve their raw source hash and additionally retain the spoken-input hash; render reports include it without adding the full sermon text. Lease timestamps are sampled after asynchronous hashing/validation and before opening the commit transaction, so that work cannot artificially extend a stale lease timestamp.

Editing current draft rules never updates existing jobs or takes. Regeneration uses a saved recording's frozen settings, including its own dictionary, regardless of current draft controls. Saved-passage UI shows original and frozen spoken input. Dictionary changes create a new recording identity; selective dictionary migration/reinterpretation of old takes is outside this slice. Playback/cache keys, undo, one-encoder exports and selected-duration podcast validation continue to use the previous milestone's immutable selection revision. Existing old recordings without rules require no new spoken-input field and remain readable/exportable.

The source fingerprint now includes the matcher and compatibility registry. Archived reviewed catalogs `render-contract-944aa8e.json` and `render-contract-1458c2e.json` allow explicit no-rule compatibility only when all other audio/dependency hashes match. The changes to recording normalization, worker dispatch and the new matcher are pinned to exact reviewed target file hashes in `pronunciation-compatibility.json`. A future edit to those files invalidates the bridge unless explicitly reviewed/re-registered. A structural test reconstructs the old worker by removing the optional pronunciation adapter and verifies its hash against the passage-takes baseline. Unknown historical dictionaries remain read/export-only if unsupported; an old no-rule recording never silently gains a dictionary.

## Reviewed overlap correction

Review of `8e3e830` found that advancing past a boundary-rejected regex match could skip a later overlapping valid spelling (`a-a` in `xa-a-a`, or `John John` in `xJohn John John`). New/edited dictionaries now use matcher v2, enumerating each Unicode-code-point start before deterministic earliest/longest selection. Replacements still never cascade. Frozen v1 dictionaries and unedited restored v1 drafts retain the exact original matching behavior; editing a draft explicitly opts into v2 and clears source-review confirmation. Matcher version remains part of frozen provenance/identity. No existing spoken hash or audio is reinterpreted.

The reviewed pronunciation catalog is archived as `render-contract-8e3e830.json`; exact compatibility pins allow its frozen v1 execution path while unknown historical inputs remain rejected. Regressions cover rejected starts, supplementary code points, overlapping accepted candidates displaced by another rule, legacy v1 resolution/identity and draft restoration. This correction is a separate commit on the stacked speech-review branch; its test/build evidence is `.cache/pronunciation-overlap-{tests,build}.log`.
