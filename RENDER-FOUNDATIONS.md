## Enabled

The app creates pcm-manifest-v3-2026-10-24 jobs. Exact source text, offset chunking and one-encoder PCM export stay intact. New jobs retain an immutable render manifest in their identity: model repository/commit, selected voice/edition, reference/style assets, tokenizer limit, pinned package versions and npm integrity, rendering-source fingerprints and processing/output contract. Each passage is bound to the job's manifest hash. Manifest mismatch or missing/invalid performance metadata aborts the atomic commit without advancing progress. A report download includes source hash, offsets, frozen inputs, durable passage observations and the last four MP3 preparations, without duplicating manuscript text or PCM.

Kokoro's installed 1.2.1 wrapper ignores revision options and hard-codes browser styles to resolve/main. A small subclass preserves its package normalizer/phonemizer but explicitly loads BOTH Transformers model and tokenizer at commit 1939ad2a8e416c0acfeecc08a694d14ef25f2231. Voice style URLs use the same immutable commit, and SHA-256/length checks apply to cached and fetched styles. Corrupt cache bytes fail closed. Normal tokenization disables truncation; 513+ post-phonemization IDs reject before model inference instead of silently truncating. This is a budget guard, not an acoustic accuracy guarantee or automatic repartitioning implementation. The pinned tokenizer configuration declares a 512-token budget.

Supertonic's existing aafc6e32416a594460b32413efc49d7fe4ce6d46 and Pocket's existing c469236dbc5f68287fa2fbf175b66de3b80123af commits are retained. Pocket's shipped reference-file digests, edition sampling settings and file paths are recorded; new-manifest conditioning verifies the reference bytes. Existing third-party character rights warnings remain applicable. No character reference was synthesized for this milestone, and no personal cloning/enrollment is enabled.

PCM replies now include schema-versioned render/provider/precision data, loading and engine-call time, model-load attempt count, fallback count, reuse state, output/synthesis durations and render RTF. The existing speech runner preserves returned object identity and text while measuring both GPU attempts and CPU retry. Engine-call time includes library text/voice processing; it is not isolated neural-kernel time. Successful passages persist these observations atomically with PCM. Cancelled/failed attempts are excluded, so these totals do not represent all session work. Empty passages are explicitly measured as empty without claiming model inference.

PCM conversion reports zero passage MP3 encoding with encoding marked deferred. Final artifact encoding has its own worker initialization, encoder CPU elapsed, worker elapsed, client preparation elapsed, samples, rate, passage count, byte count and preparation time. Reporting does not reencode or alter PCM and retains the 96 MiB per-compressed-artifact cap, existing bounded chapter cache and cancellation guards. Last-four preparation retention is bounded metadata, not a complete export history. If optional preparation-metadata storage fails (e.g. quota), playback/download remains available and the UI labels timing as unretained; core passage metadata still commits atomically with its audio.

Performance & render provenance in the reader exposes measured totals and separate artifact preparation, plus an explicitly labeled legacy state. ## Legacy and reproducibility boundaries

mp3-passages-v1 and pcm-passages-v2 normalization/identity and audio paths are retained. No database migration, source rewriting, retroactive provenance claim or automatic lossy legacy conversion occurs. Legacy timing is absent when never recorded; old model/voice revisions remain unrecorded. Continuing a legacy job retains its legacy adapter behavior; it does not silently acquire a new pinned identity, and the historical moving-Kokoro-main limitation cannot be repaired retrospectively.

Historical v3 manifests may still be validated for playback/export/report after a build changes. New inference requires the manifest to match the current supported rendering contract and rejects unsupported resumes before generation; users can create a new recording rather than mixing renderer versions. The source fingerprint is deliberately conservative, including recording/storage/export plumbing. Future renderer compatibility must be registered and tested explicitly rather than inferred from equal voice names.

Source fingerprints use UTF-8 text with CRLF normalized to LF so Windows/Linux checkouts agree; reference SHA-256 hashes cover actual binary bytes. The catalog is updated explicitly with node scripts/update-render-catalog.mjs; a test fails if render source or package lock changes without updating it. The current script reads reviewed saved public metadata (or the existing catalog), not model weights. Catalog model-file hashes come from the public Hugging Face metadata response: they are expected source metadata, not a claim that browser Transformers cryptographically checks every model file. The offline verification separately hashed local cached model/config/tokenizer files before copying them into a commit-keyed test cache. Browser voice styles and Pocket references are runtime checked. Code/package licenses do not grant speaker rights. Pinned inputs do not promise bit-identical inference across hardware or stochastic calls.
