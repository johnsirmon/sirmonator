## Reusable harness

Run `node scripts/prepare-integration-harness.mjs --port=4196`, then serve Vite on
127.0.0.1 with that port and --strictPort. Open `/.cache/integration-app.html`.
Use a fresh dedicated origin; another test port from 4100–4999 can be selected.
The fixture refuses to overwrite an unrelated draft. It never resets/deletes a
database. Existing test recordings are retained. Generated files stay in .cache
and are not wired into the production build.

The current main UI, storage, take/undo, review and MP3 worker run. Only TTS is a
clearly labeled procedural CC0 tone adapter, and the final download sink captures
up to three artifacts in memory, each capped at 8 MiB. Tone metrics explicitly say
no model inference. The inspector hashes/parses captured MP3s; it never claims a
browser download completed. Optional delayed transport makes Stop observable.
`?storage-blocked=1` injects one initial open failure; subsequent Retry uses real
IndexedDB. This is separate from the prior native two-tab blocked-upgrade test.

Deterministic `tests/combined-integration.test.js` exercises create/pause/resume,
exact source/spoken inputs, take/undo, review save/reload, stale anchors, cancellation
and real Node MP3 export together. It also validates the synthetic preview adapter.
The existing real-model script now accepts --integration to save a separate report
without replacing earlier passage-take/pronunciation evidence.
