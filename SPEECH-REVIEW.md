## Actual capability

Each saved passage can be loaded into a manual review form showing its original source, frozen spoken input, selected take/revision and exact audio SHA-256. The user can paste a transcript they supplied, explicitly state that no words were heard, or save listened/notes fields without a comparison. Listened is a human acknowledgment; the app never sets it from a matching transcript. Manual text is not evidence that the corresponding audio was heard or correctly transcribed.

The text aligner flags **possible** omitted, extra, repeated or substituted content. It accepts punctuation/case differences, NFC-equivalent word spellings and the original spelling or resolved spelling of each frozen pronunciation substitution. Internal straight/curly apostrophes are ignored in normalized words; hyphens separate tokens. Other language/number/abbreviation/phonetic expansions are not inferred. A multiword alias is a semantic alignment unit, so counts are candidate groups, not a word-error rate. Earliest/longest dictionary matching is inherited from the recording's frozen matcher version, including legacy v1 behavior where applicable.

Alignment uses bounded edit distance with whole-unit alternative spellings, not an acoustic model. Repetition candidates are inserted token blocks matching adjacent transcript text, not proof that speech repeated. Ambiguous matches and imperfect supplied transcripts can produce false positives/negatives. A zero-difference result explicitly does **not** verify audio, pronunciation, completeness or quality. There is no confidence/accuracy score, word timestamp, clipping analysis or automatic repair.

Source locations use the manuscript's absolute UTF-16 offsets; inserted transcript words anchor to a source boundary. These are text locations, not audio timestamps. The optional player shortcut loads audio near the passage's PCM-duration offset inside its chapter; MP3 padding/seeking can differ. It does not automatically play or verify the audio. The repair shortcut only opens existing passage/take controls. It never regenerates, edits source, changes rules, selects a preferred take, or alters generated audio based on alignment.

## Immutable selection and stale handling

Each review snapshot binds recording/source identity, source slice offsets/hash, frozen spoken-input hash, render-manifest hash when present, chapter, selected take, selection revision, audio format/rate/bytes and exact audio SHA-256. Snapshot keys hash that anchor. Checkpoint validation is reused before capture; PCM bytes are hashed one selected passage at a time. No full-book PCM buffer or audio copy is stored in review metadata.

Before/after comparison, save/export, playback and repair navigation, current storage is checked against the captured anchor. Changing a take, undoing, switching recordings or changing audio bytes invalidates old findings. Even an undo restoring identical original audio has a new selection revision and requires a new review. Unsaved transcript/notes remain visibly tied to the old selection and save/export are disabled until the user explicitly loads the current passage. Loading over unsaved input requires confirmation. Editing the transcript clears previous findings. Cancel/Stop rejects in-flight work and late results cannot publish into a new selection. A save already committed remains durable; cancellation does not retroactively undo it.

The reviewed audio/manuscript databases and renderer are not migrated by this UI feature. Review metadata uses a separate IndexedDB database, `sirmonator-manual-reviews-v1`. One current saved annotation/comparison is retained per exact selection; saving again replaces that selection's earlier annotations (no collaborative merge at the same anchor). Different selection revisions remain separately archived. At most 64 saved selections and 2 MiB of review JSON are retained **per recording**, enforced transactionally without automatic eviction. This is a metadata budget, not a bound on total browser, TTS-model or Blob memory.

The user can export the current review or complete saved archive as JSON, or explicitly remove reviews/clear the archive without touching audio. Export includes supplied text, manual notes, source/spoken passage text and anchored findings; it is local, never uploaded. Recording deletion's existing confirmation now includes manual reviews; review cleanup happens first, preserving the recording if that cleanup fails. Browser/site data deletion can remove local reviews; important records should be exported.

## Bounds and validation

- Transcript: 4,000 well-formed UTF-16 characters, no unsupported control characters; at most 512 comparable tokens. Empty text requires the explicit no-words observation.
- Expected alignment: at most 512 units; resolved pronunciation still obeys the existing 960-character passage limit. Three typed arrays use at most `513 × 513 × 5 = 1,315,845` bytes for DP costs/trace, plus bounded strings/tokens/findings. This is a calculated working-array cap, not a whole-process memory measurement.
- Comparison yields every 16 rows for cancellation. At most 128 candidates are displayed/exported, with the complete count and an explicit truncation flag retained. No hidden truncation of manuscript, transcript or generated audio occurs.
- Manual notes: 1,000 well-formed characters. Review storage checks snapshot/text hashes, comparison anchor and explicit `automaticTranscription:false`, `audioVerified:false`. Archive byte/count failures abort without replacing existing entries.
