# Deployed upgrade compatibility matrix

Latest baseline: `72300d892b7ea488cb752b21c6400c07bba2ae3a`. Exact old producer: deployed `c2f5cbbe980a8af6587bee3d4d95e7aa21fc5296`. This milestone changes no production code or schema and authorizes no release.

Final checks: 250 tests passed with zero failures/skips; build and diff whitespace checks passed. The ten new compatibility cases passed against actual old producer modules.

## Actual old producer, not a latest-schema imitation

`scripts/prepare-compatibility-snapshot.mjs` extracts unmodified source, JSON provenance and LAME encoder code directly from the pinned local Git commit into `.cache/compatibility-c2f5cbb`. It never checks out/reset branches or downloads assets. Static dependency extraction is bounded to source files and the known encoder. Git retains the original code; the cache copy is preserved for reproduction. `evidence/deployed-compatibility-snapshot.json` records every extracted file's SHA-256/size. No model weights or person's voice are involved.

The old recording/storage/metrics/codec modules actually create schema-v1 synthetic recordings. Latest storage adds schema-v2 takes support, and latest validation/export reads those records. Old/new artifact comparisons use each version's actual encoder worker and bundled encoder. Their relative encoder URL is adapted only for the Node test environment. Fixtures use procedural CC0 tones, not synthesis or speech.

| Old-produced variant | Latest result |
| --- | --- |
| `mp3-passages-v1-2026-10-23` | Original committed MP3 bytes exported unchanged; no lossy migration |
| `pcm-passages-v2-2026-10-24` | Single-artifact MP3 hash identical to old export; missing model provenance reported |
| `pcm-manifest-v3-2026-10-24` | Frozen inputs preserved; single-artifact MP3 hash identical to old export |
| Partial supported deployed frozen record | Saved prefix kept; only remaining passages generated through synthetic stub |
| Partial unsupported frozen source contract | Inference rejected before callback; saved prefix still exports |
| Malformed PCM length / changed source offsets | Publication rejected before encoder creation; stored rows retained |
| Same-size bit flip in an old original without checksum | Cannot be detected historically; remains explicitly labeled checksum-unrecorded |

All variants preserve draft/source/part bytes. No checksum, missing historical provenance or model revision is invented. Supported partial legacy resumes can add hashes to new PCM parts while older parts remain historically unrecorded; their frozen identity is not rewritten. This is not a blanket guarantee for arbitrary unknown/future schemas.

## Lifecycle/failure envelope

Ten targeted deterministic tests use production APIs and fake-indexeddb, with records generated by actual old APIs. They exercise an old live connection closing on versionchange, a deliberately held blocking connection, abandoned late upgrade, explicit retry, cancellation before upgrade work, and transaction failure after the takes store is created. Interrupted/failed upgrades roll back to schema v1, retaining the original stores/data; retry then succeeds. No database deletion/reset is used.

Deployed c2f5cbb predates manual-review/reference side databases. A separate coexistence test creates current v1 side metadata while recordings are still v1, closes/reopens all stores across the recordings upgrade, and verifies the exact review and consent/inspection envelope survives. The reference is a procedural three-second CC0 tone; no audio/embedding is placed in its metadata record. Revocation still works. This does not claim testing every intermediate historical side-database implementation.

## Reproduction

```powershell
node --test tests/deployed-upgrade-compatibility.test.js
node scripts/run-deployed-compatibility.mjs
```

The second command writes snapshot and byte-comparison evidence. To repeat the browser fixture, extract the snapshot, prepare the existing integration harness with `--port=4204`, serve loopback on port 4204, and use a fresh isolated browser storage context. Do not clear or reset existing data to force a repeat.

No real-model inference, pronunciation/acoustic quality, phone limits, every browser, future-version downgrade, actual device quota failure or full-size historical user recording is verified here. The deployment remains unchanged.

Historical original MP3/PCM without stored checksums is not authenticated against arbitrary same-size byte corruption. Structural validation and successful short playback do not establish integrity of every old frame; no automatic lossy repair or checksum backfill is performed.
